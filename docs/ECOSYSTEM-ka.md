## 1. მოკლედ: რა არის CDC პლატფორმა

**CDC (www.cdc.org.ge)** არის ერთიანი ონლაინ პლატფორმა, რომელიც აერთიანებს:

- **სწავლებას** — ონლაინ კურსები სერტიფიკატით, ლაივ ტრენინგები, AI კარიერული ტესტი, ვიდეო ინსტრუქციები.
- **AI ხელსაწყოებს** — მაგ. საბავშვო წიგნის გენერატორი, AI ინგლისურის რეპეტიტორი (IMIAKO), AI ჩატბოტის კონსტრუქტორი ბიზნესისთვის, AI გამოცდები მონიტორინგით, მედია სტუდიო.
- **მაღაზიას** — ციფრული პროდუქტები (ელ. წიგნები, დიზაინი, შაბლონები), რომლებსაც ავტორები ყიდიან და CDC იღებს საკომისიოს.
- **კარიერას** — ვაკანსიები, ფრილანს შეკვეთები (gigs) დაცული გადახდით (escrow), მენტორები, ფორუმი.
- **CDC სტუდიოს** — ციფრული სერვისები ბიზნესისთვის (განაცხადები, ქეისები).
- **ადმინ პანელს** — სადაც ყველაფერს მართავ: მომხმარებლები, კონტენტი, ფინანსები, პრომო კოდები და ა.შ.

## 2. ერთი სურათით: როგორ არის აწყობილი

```
   ვიზიტორი (ბრაუზერი / ტელეფონი)
              │
              ▼
 ┌────────────────────────────┐
 │  FRONTEND — საიტის „სახე“   │   Vercel (ავტომატურად ახლდება, როცა
 │  Next.js, www.cdc.org.ge   │   კოდი main-ში ერთიანდება)
 └────────────┬───────────────┘
              │  API მოთხოვნები (/api/...)
              ▼
 ┌────────────────────────────┐
 │  BACKEND — „ტვინი“          │   Azure App Service: cdc-api-prod
 │  Express + Node.js          │   (CDC-Prod-RG, P0v3, პორტი 5000)
 │  Docker კონტეინერში          │   ახლდება მხოლოდ ხელით (deploy)
 └──┬─────────┬─────────┬─────┘
    │         │         │
    ▼         ▼         ▼
 ┌───────┐ ┌────────┐ ┌──────────────────────────────┐
 │ ბაზა  │ │ ფაილები │ │ გარე სერვისები                │
 │Postgres│ │Azure   │ │ AI: Gemini, Azure OpenAI,     │
 │cdc-    │ │Blob,   │ │     gpt-image-2 (სურათები),   │
 │postgres│ │Bunny   │ │     Azure Speech (ხმა)        │
 │-prod   │ │CDN/    │ │ გადახდა: BOG, Stripe          │
 │(Prisma)│ │Stream  │ │ ელფოსტა: Resend; WhatsApp     │
 └───────┘ └────────┘ └──────────────────────────────┘
```

| ნაწილი | რა არის | სად ცხოვრობს |
|---|---|---|
| **Frontend** (ფრონტენდი) | ის, რასაც ვიზიტორი ხედავს: გვერდები, ღილაკები, ფორმები. დაწერილია Next.js-ზე. | **Vercel**. როცა PR ერთიანდება `main`-ში, Vercel თავად აახლებს საიტს რამდენიმე წუთში. |
| **Backend** (ბექენდი) | სერვერი, რომელიც ამუშავებს ლოგიკას: შესვლა, გადახდა, AI-ს გამოძახება, ბაზაში ჩაწერა. Express + TypeScript. | **Azure App Service `cdc-api-prod`** (რესურს ჯგუფი `CDC-Prod-RG`, ტარიფი P0v3). მუშაობს Docker კონტეინერში, „sitecontainers“ რეჟიმში (კონტეინერის სახელი `main`). **ავტომატურად არ ახლდება** — საჭიროა ხელით deploy (იხ. ნაწილი 11). |
| **მონაცემთა ბაზა** | სადაც ინახება ყველაფერი: მომხმარებლები, კურსები, გადახდები, წიგნები. | **Azure PostgreSQL Flexible Server `cdc-postgres-prod`** (v18, B1ms). ბაზასთან კოდი ურთიერთობს **Prisma**-ს მეშვეობით. |
| **Prisma** | „თარჯიმანი“ კოდსა და ბაზას შორის. ფაილი `Backend/prisma/schema.prisma` აღწერს ბაზის ყველა ცხრილს (~130 მოდელი). ცვლილებები ბაზის სტრუქტურაში ხდება **მიგრაციებით** (`Backend/prisma/migrations/`, ~165 ცალი). | კოდში |
| **ფაილების საცავი** | ფოტოები, ვიდეოები, გასაყიდი ფაილები, წიგნის სურათები. | **Azure Blob Storage** (პირადი ფაილები, მაგ. გაყიდული პროდუქტები, ლექციის ვიდეოები) და **Bunny CDN / Bunny Stream** (საჯარო სურათები და ვიდეო სტრიმინგი). |
| **კოდი** | ყველაფრის წყარო. | GitHub: `cdc-platform-org/cdc-platform` |

**მნიშვნელოვანი განსხვავება:**
- Frontend-ის ცვლილება (მხოლოდ დიზაინი/ტექსტი/გვერდი) → PR-ის merge-ის შემდეგ **თავისით** ჩნდება საიტზე.
- Backend-ის ცვლილება (ახალი ფუნქცია სერვერზე, ბაზის ცვლილება) → merge-ის შემდეგ **საჭიროა deploy** Azure-ზე, თორემ საიტზე არ იმუშავებს.

## 4. AI ხელსაწყოები

ყველა AI ტექსტური ფუნქცია გადის **ერთ „კარიბჭეზე“** (`Backend/src/services/aiAgentService.ts`). თუ ერთი AI მოდელი არ პასუხობს, ავტომატურად ცდის შემდეგს:

1. Gemini Flash → 2. Gemini Flash Lite → 3. Gemini 3.5 Flash → 4. **Azure OpenAI GPT-4o** (სათადარიგო).

ასე ერთი პროვაიდერის გათიშვა მთელ საიტს არ აჩერებს. (სურათის ანალიზზე სათადარიგო ვარიანტი არ არის.)

### 4.1. საბავშვო წიგნის გენერატორი (Children's Book)
- **სად:** `/dashboard/tools/childrens-book`; წამკითხველი: `/ka/dashboard/tools/childrens-book/reader/<bookId>`; მართვა: `/ka/dashboard/tools/childrens-book?bookId=<id>`.
- **რას აკეთებს:** მშობელი ავსებს ინფორმაციას ბავშვზე (სახელი, ასაკი, ფოტო, შესაძლოა და-ძმაც ფოტოებით), ირჩევს სტილს — AI წერს პერსონალურ ზღაპარს და ხატავს ილუსტრაციებს, სადაც ბავშვი არის მთავარი გმირი. შედეგი: ონლაინ წიგნი + PDF, შესაძლოა ხმოვანი გახმოვანებით.
- **ეტაპები:** ინფორმაცია → თანხმობა (ფოტოს გამოყენებაზე) → გადახდა → ისტორიის გეგმა → ტექსტი → სურათები → ხარისხის შემოწმება → PDF.
- **სტილები:** 6 ილუსტრაციის სტილი (watercolor ცოცხლად შემოწმებულია; ყველა 6-ის ჩართვა PR #38-შია).
- **ტექნიკა:** სურათები — Azure `gpt-image-2` (რესურსი `cdc-book-images`); ტექსტი — AI კარიბჭე; ხმა — Azure Speech. **ერთი წიგნის თავიდან გენერაცია ≈ 10 სურათი = ხარჯი.**
- **კოდი:** `Backend/src/routes/childrensBook.ts`, `Backend/src/services/book*.ts`.

### 4.2. IMIAKO — AI ინგლისურის რეპეტიტორი
- **სად:** `/dashboard/english-tutor`.
- კითხვა, წერა, გრამატიკა, ლექსიკა, მოსმენა და დიალოგი — მომხმარებლის დონეზე (A1–C1), ახსნა მის ენაზე. აქვს უფასო ლიმიტი და **PRO გამოწერა** (პრომო კოდითაც).
- **კოდი:** `routes/englishTutor.ts`, `services/englishTutor*.ts`. ადმინში: `/admin/tutor`.

### 4.3. IAKO — AI ასისტენტი სწავლისთვის
- **სად:** `/dashboard/iako`.
- AI ასისტენტი, რომელსაც ტრენერი/ადმინი აკონფიგურირებს კონკრეტული კურსისთვის ან ჯგუფისთვის („პროფილები“). მოსწავლეს შეუძლია ჰკითხოს, ეკრანის ფოტოც გაუგზავნოს (მაქს. 3 სურათი შეტყობინებაზე). აქვს საათობრივი/დღიური ლიმიტები.
- ადმინში: `/admin/iako/profiles`, `/admin/iako/usage`.

### 4.4. Enterprise AI ასისტენტი (ჩატბოტის კონსტრუქტორი)
- **სად:** `/dashboard/tools/chatbot-builder`.

## 7. გადახდები და ფული

- **BOG (საქართველოს ბანკი)** — მთავარი გადახდის სისტემა ლარში. ბანკი შედეგს გვიგზავნის ხელმოწერილი შეტყობინებით (webhook), რომელსაც სერვერი ამოწმებს, რომ ყალბი არ იყოს.

- **საკომისიო:** მაღაზიის პროდუქტზე და ფრილანს შეკვეთაზე CDC იღებს **20%**-ს.
- **ფასდაკლება:** მინიმუმ 2 ლარი რჩება (ბანკის საკომისიოს გამო); პროდუქტზე მაქს. 80%, კურსზე მაქს. 90%. ფასდაკლების ვადა ავტომატურად იწურება.
- **Escrow (დაცული გადახდა)** — ფრილანს შეკვეთაზე, მენტორობაზე, HR მხარდაჭერაზე: დამკვეთის ფული „იყინება“ და შემსრულებელს ერიცხება სამუშაოს დასრულების შემდეგ.
- **გაყიდული ფაილები** დაცულია: ინახება დახურულ საცავში, მყიდველი იღებს 15-წუთიან დროებით ბმულს. პრევიუ სურათებზე ედება „CDC.ORG.GE“ წყლის ნიშანი.
- **ავტორებისთვის ავტომატური გადარიცხვა (BOG Mass Payout)** — ჯერ არ არის მზად, საჭიროა ბანკთან ხელშეკრულება.
- **თანხის დაბრუნება (Refund)** — ადმინში ღილაკი მზადაა PR #20-ში (ჯერ არ არის გაშვებული).

## 11. როგორ ხდება ცვლილების გაშვება (Deploy)

### ნაბიჯი 0 — ცვლილება
ყოველი ცვლილება მოდის **PR**-ით (Pull Request). PR-ის merge-ის შემდეგ კოდი ხვდება `main` ფილიალში.

### Frontend
merge → **Vercel ავტომატურად** აახლებს საიტს. არაფერი გჭირდება.

### Backend (ხელით, დაცული პროცესით)
1. დაელოდე, რომ **Nightly QA** იყოს მწვანე ✅ `main`-ის **ბოლო commit-ზე** (ან გაუშვი ხელით: Actions → Nightly QA → Run workflow).
2. GitHub → **Actions** → **„Build and deploy container to Azure Web App - cdc-api-prod“** → **Run workflow**.
3. „Use workflow from“ = **main**.
4. **deploy_sha** = `main`-ის ბოლო commit-ის **სრული 40-სიმბოლოიანი კოდი** (SHA). (GitHub → Code → commits → ასლის ღილაკი.)
5. მონიშნე **acknowledge_startup_migrations** (ნიშნავს: „ვიცი, რომ ახალი კონტეინერი ჩართვისას ბაზაში მიგრაციებს გაუშვებს“).
6. **Run workflow** → შემდეგ დაადასტურე (**Approve**) „Production“ გარემოში.
7. დაელოდე მწვანე შედეგს. პროცესი თავად აშენებს Docker სურათს, ცვლის კონტეინერს, აკეთებს რესტარტს და **ამოწმებს**, რომ ნამდვილად ახალი ვერსია მუშაობს.

**დამცავი წესები** (პროცესი უარს იტყვის, თუ):
- გაშვებულია არა `main`-იდან;
- SHA არ არის `main`-ის ბოლო commit;
- ამ SHA-ზე Nightly QA არ არის მწვანე;
- მიგრაციის მონიშვნა გამოტოვებულია;
- Azure აპი არ არის „sitecontainers“ რეჟიმში.

**ცნობილი პრობლემა:** თუ კონტეინერი რამდენიმე დღეა მუშაობს, Azure შლის ძველ ლოგს და პროცესი წერს „Running image: not verified“. **გამოსავალი:** Azure Portal → `cdc-api-prod` → **Restart** (იგივე ვერსია), შემდეგ deploy-ის თავიდან გაშვება (Re-run).

**მიგრაციები:** ახალი კონტეინერი ჩართვისას თავად უშვებს `prisma migrate deploy`-ს. თუ მიგრაცია ჩავარდა, კონტეინერი არ ჩაირთვება (რომ ძველ სტრუქტურაზე არ იმუშაოს).

> შენიშვნა: Claude-ის thread-ებს deploy-ის გაშვება არ შეუძლიათ — მას ყოველთვის შენ უშვებ და ადასტურებ.

## 12. როგორ დავაბრუნოთ ძველი ვერსია (Rollback)

თუ ახალი ვერსია პრობლემას იწვევს:

1. გაიგე წინა სწორი ვერსიის SHA (მაგ. deploy-ის ისტორიიდან GitHub Actions-ში, ან ამ დოკუმენტის ბოლოს „ვერსიების ისტორია“).
2. Azure Portal → `cdc-api-prod` → **Deployment Center** (Site Containers) → კონტეინერი **`main`** → სურათის ტეგი შეცვალე ძველ SHA-ზე (`cdcplatformacr.azurecr.io/cdc-platform-backend:<ძველი-SHA>`).
3. **Save** → **Restart**.

⚠️ **მნიშვნელოვანი:** ბაზის მიგრაციები **უკან არ ბრუნდება** ავტომატურად. ძველი კოდი ჩვეულებრივ მუშაობს ახალ ბაზაზე (მიგრაციები ძირითადად მხოლოდ ამატებენ), მაგრამ თუ მიგრაციამ რამე წაშალა/შეცვალა, საჭიროა ცალკე გეგმა.

**Frontend-ის rollback:** Vercel → Deployments → აირჩიე წინა წარმატებული → **Promote to Production** (ან „Instant Rollback“).

## 13. მონაცემთა ბაზა და სარეზერვო ასლები

- **სერვერი:** `cdc-postgres-prod` (PostgreSQL 18, ტარიფი B1ms — „burstable“, ეკონომიური).
- **სარეზერვო ასლები:** ავტომატური ყოველდღიური + **7 დღის Point-in-Time Restore** (შეგიძლია ბაზა დააბრუნო ნებისმიერ წუთზე ბოლო 7 დღის განმავლობაში). ამ ტარიფზე **ხელით „ახლავე backup“ არ არის**.
- **აღდგენა:** Azure Portal → `cdc-postgres-prod` → **Backup and restore** → **Restore** → აირჩიე დრო. აღდგება **ახალ სერვერად** (ძველი არ იშლება), შემდეგ `DATABASE_URL` უნდა გადაერთოს.
- **სტრუქტურა:** `Backend/prisma/schema.prisma`. ცვლილება მხოლოდ მიგრაციით.
